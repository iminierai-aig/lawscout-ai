## 6. Authentication lockout incident and hotfix

After `v2.1.3`, users with an invalid pre-deployment token could see the homepage but clicking Sign In or Sign Up appeared to do nothing.

Root cause:

- The client removed an invalid token from local storage.
- The corresponding cookie remained.
- Next.js middleware treated cookie presence as valid authentication and redirected `/login` and `/register` back to `/` without validating the token.

Commit: `b711021` — `fix(auth): allow recovery from stale session cookies`

Fixed by:

- Clearing the middleware cookie when token validation fails.
- Removing middleware redirects that treated unvalidated cookie presence as authenticated state.
- Retaining protection for routes that require a cookie.

Release: `v2.1.4`

Successful publication run: `30672971312`

Immediate user recovery was also possible by clearing site data or using an incognito window. After frontend deployment, login and registration worked normally.
